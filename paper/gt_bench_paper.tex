\begin{abstract}
GT-Bench is a compact benchmark for measuring whether targeted fine-tuning improves a narrow, exactly verifiable formal reasoning task. Each canonical example gives a randomly generated 2x2 two-player normal-form payoff matrix and asks a model to identify all pure-strategy Nash equilibria. Because the task has an exact solver, data can be generated at scale and model outputs can be scored without subjective judgment. Using Thinking Machines Lab Tinker, LoRA supervised fine-tuning of \modelname{} on 5000 synthetic examples improved canonical exact-match accuracy from 87.60\% to 99.60\%. A three-seed learning curve found that the 5000-example condition was stable, with 99.60\% mean accuracy and 0.40 percentage-point seed standard deviation, while the 1000-example condition was volatile. A conservative 500-example adversarial prompt supplement further improved prompt-robustness accuracy from 88.40\% to 98.80\% relative to the original 5000-example checkpoint, without reducing canonical accuracy. A separate six-family suite pilot improved broader-suite accuracy from 20.00\% to 68.00\%, but the suite-specific checkpoint retained only 53.60\% canonical accuracy. The result supports a narrow claim: targeted fine-tuning can improve one controlled formal reasoning skill, and targeted adversarial data can improve robustness to equivalent prompt presentations. It does not demonstrate broad game-theory reasoning competence.
\end{abstract}

\section{Introduction}

Large language models often appear capable of formal reasoning, but broad qualitative examples make it difficult to separate rule acquisition from prompt familiarity, memorized patterns, or forgiving evaluation. The reported GT-Bench experiment isolates one small mathematical task: given a 2x2 normal-form game, return exactly the set of pure-strategy Nash equilibria. The benchmark is intentionally narrow, synthetic, and mechanically verifiable. It is a benchmark instance for one equilibrium-finding rule, not evidence of broad game-theory competence.

The experimental question is practical: can targeted supervised fine-tuning measurably improve a model on a precisely specified formal game-theory skill? The project was developed as a public research artifact for a Thinking Machines Lab Tinker research grant. The canonical experiment's design goal is control: one task, one exact solver, deterministic data generation, exact-match scoring, and focused robustness checks.

The main result is positive. On the canonical 500-example held-out test split, \modelname{} improved from 87.60\% exact-match accuracy at baseline to 99.60\% after LoRA supervised fine-tuning on 5000 synthetic examples. The improvement held on an independent confirmation set, became sharper on a balanced stress set, and remained stable in a three-seed training-data sweep. A follow-up adversarial prompt supplement then closed most of the remaining prompt-format robustness gap. The repository also includes a separate exactly scored suite for broader game-theory tasks. The suite pilot is reported separately because its best suite-specific checkpoint improves the broader suite but forgets much of the canonical task.

\section{Related Work}

GT-Bench sits at the intersection of formal reasoning evaluation, synthetic verifiable tasks, parameter-efficient fine-tuning, and LLM game-theory evaluation. Mathematical reasoning benchmarks such as GSM8K and MATH evaluate models on natural-language math problems with exact or semi-exact final answers \cite{cobbe2021gsm8k,hendrycks2021math}. Code benchmarks such as HumanEval and LiveCodeBench use executable tests or live contamination-limited problem streams to reduce subjective grading and benchmark leakage \cite{chen2021codex,jain2024livecodebench}. Recent arithmetic benchmark work also emphasizes the need to distinguish generalization from memorization when benchmark items may appear in pretraining data \cite{zhang2024gsm1k}. GT-Bench follows this verifiable-evaluation direction but uses a fully synthetic, regenerable task with an exact solver.

The fine-tuning intervention uses LoRA \cite{hu2022lora}, a parameter-efficient adaptation method. The base model is \modelname{}, a 27B open-weight Qwen3.6 model distributed by the Qwen team under Apache 2.0 \cite{qwen36modelcard}; its broader model family is described in the Qwen3 technical report \cite{yang2025qwen3}. Training was run with Tinker, a managed fine-tuning API that exposes LoRA training and sampling while handling distributed infrastructure \cite{tinker2025}.

There is also a growing body of work on LLMs and strategic reasoning. Surveys frame this area as including game-based evaluation, game-theoretic alignment, and LLM-assisted game analysis \cite{sun2025gametheorysurvey}. Existing game-theory-oriented LLM benchmarks such as GTBench evaluate broader strategic behavior in game environments \cite{duan2024gtbench}. The experiment in this paper is deliberately narrower: it does not evaluate play, negotiation, mixed strategies, or strategic interaction. It tests whether a model can learn one explicit equilibrium-identification rule for 2x2 normal-form games.

\section{Task Definition}

Each example is a two-player normal-form game. Player 1 chooses $U$ or $D$, and Player 2 chooses $L$ or $R$. Each cell contains an ordered pair of integer payoffs in the range 0 through 9. A pure-strategy Nash equilibrium is a strategy profile in which both players are best responding to the other player's strategy \cite{nash1950equilibrium,nash1951noncooperative}. Ties are handled exactly, so a game may have zero, one, two, three, or four pure equilibria.

The reported model experiment deliberately excludes mixed strategies, dominance, welfare analysis, sequential games, auctions, public goods games, Nim, and natural-language story problems. This restriction is central to the main result. The goal is to evaluate one rule under controlled conditions, not to claim broad game-theory performance.

\section{Broader Suite Infrastructure}

The public repository now also contains a broader suite generator and scorer. This suite covers six additional task families: fully mixed equilibria in 2x2 games with no pure equilibrium, iterated elimination of strictly dominated pure strategies, pure equilibria in 2x3 and 3x3 normal-form games, backward induction in perfect-information extensive-form games, natural-language game descriptions, and finite repeated prisoner's-dilemma simulations plus best-response selection among fixed policies. Each family has deterministic generation, exact solver metadata, difficulty buckets, train/validation/test split generation, task-family scoring, local smoke baselines, and an oracle check.

The suite test split contains 300 examples, 50 from each family. Table~\ref{tab:suite-pilot} reports the completed Tinker pilot. \section{Data, Leakage Controls, and Scoring}

The canonical dataset uses random seed 42 and contains 5000 training examples, 500 validation examples, and 500 held-out test examples. The generator samples eight integer payoffs independently from 0 through 9, rejects duplicate payoff matrices, and then slices one jointly generated sequence into train, validation, and test splits. This makes the canonical train/validation/test matrices disjoint by construction.

Additional evaluation sets were generated from separate seeds: a 1000-example confirmation set, a 250-example balanced stress set, and a 250-example prompt-robustness set. A signature audit over payoff matrices found no overlap between the canonical training split and the validation, canonical test, confirmation, stress, robustness, or adversarial supplement files. The adversarial supplement also avoids canonical training matrices by construction. It has one payoff-matrix overlap with the balanced stress set; the stress result is therefore reported mainly as a sanity check for the adversarial run, not as its primary evidence. The prompt-robustness result is the central adversarial follow-up.

The exact solver computes each player's best responses by column and row, then returns exactly those cells in which both players are best responding. The scorer parses common answer forms such as \texttt{(U, L)}, \texttt{U,L}, and natural-language empty-set statements such as \texttt{none} or \texttt{no pure Nash equilibrium}. Predictions are converted into sets and compared to the solver output while ignoring order. Accuracy is exact-match accuracy: a prediction is correct only if it names exactly the gold equilibrium set. Unparseable predictions are scored incorrect. In the audited canonical baseline, canonical 5000-example SFT, adversarial canonical, and adversarial robustness prediction files, the parser found a prediction set for every example.

\section{Fine-Tuning Setup and Baselines}

The base model was \modelname{}. Experiments used the Tinker \texttt{qwen3\_disable\_thinking} renderer and LoRA supervised fine-tuning \cite{hu2022lora} with rank 16, 3 epochs, effective batch size 32, maximum length 4096, and learning rate $10^{-4}$. Decoding used temperature 0, one sample, and a 768-token maximum. Three canonical training sizes were evaluated: 250, 1000, and 5000 examples.

The local run manifests record 21 training steps for the 250-example runs, 93 steps for the 1000-example runs, 468 steps for the 5000-example runs, and 513 steps for the 5500-example adversarial run. Observed wall-clock training time was approximately 1--2 minutes for 250 examples, 6--7 minutes for 1000 examples, 31--32 minutes for 5000 examples, and 34 minutes for the adversarial 5500-example run. Exact token-billing and credit consumption were not committed to the public artifact; raw run manifests are intentionally ignored because they contain private Tinker sampler and state paths.

The main learned baseline is the unmodified base model evaluated with the same deterministic decoding. Simple non-learned baselines are much weaker on the canonical test set: always predicting no pure equilibrium gets 45/500 examples correct (9.00\%); always predicting the most frequent single equilibrium set, either $(U,L)$ or $(D,R)$ on this split, gets 83/500 correct (16.60\%); uniformly guessing one of the 16 possible profile subsets has expected exact-match accuracy 6.25\%. The exact solver is used only to generate labels and score predictions, not as a learned baseline.

\section{Prompt Robustness}

A 250-example robustness set tested five semantically equivalent prompt surfaces: the original table, compact payoff pairs, JSON-like payoff objects, a minimal matrix, and an answer-only instruction. The base model achieved 64.00\% exact-match accuracy (95\% CI: 57.71--69.95\%), while the original 5000-example checkpoint achieved 88.40\% (95\% CI: 83.77--92.09\%). This improved robustness substantially, but \texttt{compact\_pairs} and \texttt{json\_payoffs} remained weak at 78.00\% and 68.00\%, respectively.

\section{Failure Modes}

Before fine-tuning, the dominant failure mode was false positives on games with no pure equilibrium. The model frequently selected at least one cell even when no cell was a mutual best response. After 5000-example fine-tuning, this failure mode was mostly removed. The remaining canonical and confirmation failures in the best non-adversarial checkpoint are tie-heavy games where the model identifies true equilibria but over-predicts one extra cell.

\section{Code, Data Availability, and Ethics}

The code is available at \repo{} under the MIT License. The repository tracks the canonical generator, solver, scorer, broader suite generator/scorer/baselines, Tinker scripts, public summaries, figures, and this paper source. Generated JSONL data, raw predictions, raw reports, and Tinker run manifests are ignored by default because they are reproducible and can contain private sampler paths. Public summary JSON files, SVG figures, and small sample JSONL files are tracked.

This work uses synthetic payoff matrices and does not involve human subjects or personal data. The main risk is interpretive: the result could be overstated as evidence of broad game-theory ability. The headline model-result claim supports only 2x2 pure-equilibrium identification under the tested Tinker setup. The broader-suite pilot is diagnostic and shows that suite adaptation can come with substantial canonical forgetting. Reproduction also depends on access to the same or comparable Tinker model, renderer, and pricing environment.

\section{Limitations}

The reported GT-Bench experiment is not a general game-theory evaluation. It uses synthetic data, only 2x2 games, only integer payoffs, and only pure-strategy equilibria. The repository's broader suite adds exact artifact coverage for mixed strategies, dominance, larger normal-form games, sequential reasoning, natural-language descriptions, and repeated interaction, and the first suite-specific Tinker run improves that suite. However, its weak canonical retention shows that this is not yet a unified game-theory capability result. The result also does not prove that the model acquired a human-like concept of Nash equilibrium.

The benchmark is useful precisely because it is constrained. The rule is exact, the data is reproducible, and failures can be inspected mechanically. The appropriate claim is narrow: targeted fine-tuning can improve this specific formal reasoning behavior under the tested conditions.

\section{Conclusion}

GT-Bench demonstrates that a compact, reproducible Tinker fine-tuning artifact can produce measurable gains on a fully verifiable formal reasoning task. The strongest non-adversarial checkpoint improved canonical accuracy from 87.60\% to 99.60\%, the three-seed sweep showed that the 5000-example condition was stable, and an adversarial prompt supplement improved robustness from 88.40\% to 98.80\% relative to the original 5000-example checkpoint. The conclusion is deliberately narrow but useful: targeted fine-tuning can improve a specific formal skill, and targeted data can close prompt-format robustness gaps for that same skill. The broader-suite pilot makes the next evaluation layer concrete, while its poor canonical retention shows why broader claims require a multitask or retention-aware follow-up.

\section{Scoring Details}

The parser first prefers text after the last \texttt{Final answer:} or \texttt{Conclusion:} marker, then searches answer-like sentences, then falls back to the whole output. If an empty-set phrase appears before any profile mention in the candidate span, the prediction is parsed as the empty set. Otherwise, all profile mentions matching \texttt{U} or \texttt{D} paired with \texttt{L} or \texttt{R} are extracted into a set. Order and duplicate mentions do not matter. If no prediction can be parsed, the example is scored incorrect.

The test suite covers solver behavior for one-equilibrium, two-equilibrium, no-pure-equilibrium, and tie-heavy games, as well as common parser formats. The scorer intentionally remains simple so failures are inspectable.
